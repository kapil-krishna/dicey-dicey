# Dicey Dicey Features & Requirements

## Overview

Dicey Dicey is a simple Android dice rolling application.

The application simulates rolling a standard six-sided die. The user interacts only with the die itself: tap the die to roll, watch the animation, and see the resulting face.

The goal of version 1 is a polished, minimal experience with simple and predictable behaviour.

---

# Version 1 Scope

Version 1 includes:

- A single six-sided die
- Tap-to-roll interaction
- Animated rolling behaviour
- Random result generation
- Programmatically rendered die faces
- Ability to roll again immediately after completion

Version 1 intentionally avoids additional features that are not required for the core experience.

---

# User Interaction

## Initial State

When the app opens:

- A single die is displayed.
- The die shows an initial face value.
- The die is ready to be rolled.
- No buttons or additional controls are displayed.

The entire visible die area should respond to taps.

---

## Starting a Roll

When the user taps the die:

- The die immediately begins rolling.
- The application generates a new random result.
- The rolling animation begins.

The user does not need to press any buttons or confirm the action.

---

## Rolling Behaviour

The rolling sequence has two phases:

### Phase 1: Rolling Animation

During the rolling phase:

- The die should visibly move and shake.
- The animation should feel unpredictable and dynamic.
- The final result should not be obvious immediately.
- The animation should run for approximately 5 seconds.

### Phase 2: Settling Animation

After the rolling phase:

- The die transitions smoothly into its final position.
- The final face value is displayed clearly.
- The animation ends naturally rather than stopping abruptly.

After settling:

- The die returns to the ready state.
- The user can immediately tap again to start another roll.

---

# Random Result Requirements

The application represents a standard six-sided die.

Requirements:

- Valid results are integers from 1 to 6.
- Each possible result must have an equal probability.
- Previous rolls must not affect future rolls.
- The application does not need to store roll history.

Example:

1 → 1/6 probability
2 → 1/6 probability
3 → 1/6 probability
4 → 1/6 probability
5 → 1/6 probability
6 → 1/6 probability


---

# Die Display Requirements

The die should visually represent a normal six-sided die.

Requirements:

- All faces from 1 to 6 must be supported.
- Dot layouts must match a traditional die.
- The face should remain readable on different screen sizes.
- The die should be visually centred on screen.

The die face should be generated by code rather than relying on external image files.

---

# Animation Requirements

The animation should provide the feeling of a physical die being rolled.

Requirements:

- Smooth motion.
- No visible frame stuttering during normal operation.
- The die should move while rolling.
- The transition into the final result should feel natural.

The animation does not need to simulate real-world physics.

A convincing visual effect is more important than physical accuracy.

---

# Touch Behaviour

## Supported Interactions

### Tap

A normal tap on the die:

- Starts a roll when idle.
- Does nothing while the roll animation is already running.

---

## Unsupported Interactions

The following are not supported in version 1:

- Long press actions.
- Multiple touch gestures.
- Swipe gestures.
- Buttons or menus.
- Changing dice type.

---

# Application States

The application has two user-visible states:

## Ready

The die:

- Displays the current result.
- Waits for user input.
- Can be tapped to start a new roll.

## Rolling

The die:

- Runs the rolling animation.
- Ignores additional input.
- Transitions automatically to the final result.

---

# Non-Functional Requirements

## Simplicity

The application should remain small and focused.

Avoid adding:

- Unnecessary screens.
- Complex configuration.
- Features unrelated to rolling a die.

---

## Performance

The application should:

- Start quickly.
- Maintain smooth animation.
- Work across common Android screen sizes.

---

## Dependencies

The application should minimise dependencies.

Only required Android and AndroidX libraries should be used.

---

# Out of Scope for Version 1

The following features are intentionally excluded:

- Multiple dice
- Different dice types (D4, D8, D10, D12, D20)
- Roll history
- Statistics
- Sound effects
- Themes
- Customisation
- Online features
- Accounts
- Leaderboards
- Settings screens
- Interrupting a roll with a second tap

These may be considered for future versions but are not part of the initial implementation.

---

# Acceptance Criteria

Version 1 is complete when:

- [ ] The app opens showing a die.
- [ ] Tapping the die starts a rolling animation.
- [ ] A random value from 1–6 is selected.
- [ ] The rolling animation runs for approximately 5 seconds.
- [ ] The die smoothly settles on the final result.
- [ ] All six die faces render correctly.
- [ ] The user can immediately start another roll after completion.
- [ ] Additional taps during rolling do not interrupt the animation.
- [ ] The application builds successfully.
- [ ] Automated tests cover core dice logic.
